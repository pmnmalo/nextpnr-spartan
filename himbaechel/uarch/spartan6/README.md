# spartan6: the Xilinx Spartan-6 in nextpnr-himbaechel

A Himbaechel micro-architecture for the Spartan-6 (XC6SLX16, XC6SLX45), developed for
[Silinx ISE](https://github.com/pmnmalo/Silinx-ISE) ([Silinx #2138](https://github.com/pmnmalo/Silinx-ISE/issues/2138)).

## What it does

It takes either of two netlists:
- **Yosys's** (`synth_xilinx -family xc6s`, Silinx's synthesis), which it packs into sites itself (Silinx #3135) and whose
  pads and global buffers it places by Silinx's rules (#3136), below;
- **whole sites**, as Silinx's own Map packs them (its `src/fpga/s6/pack.js`, `phys.js`, `nextpnr.js`: SLICEX / SLICEL /
  SLICEM, IOB, BUFGMUX, RAMB16BWER / RAMB8BWER, DSP48A1 and TIEOFF cells whose ports are the sites' pins), placed and
  routed as they are. Silinx's flow, `src/open-flow-nextpnr-s6.js`: a placement, with the pads and global buffers fixed
  by Silinx (attribute `BEL`), and the block RAMs and DSP48A1s until Silinx leaves them to nextpnr (#3137); then the
  placed design written with its constants' sources (TIEOFFs), and routed with `--no-place`.

Silinx writes the sites' settings itself afterwards (`xdl.js`).

## The packer

`pack.cc`, `phys.cc`, `phys_mem.cc` and `arcs.cc` follow Silinx's Map step by step (`pack.js`, `phys.js`, `phys-mem.js`,
`timing-arcs.js`), so that a netlist packs into the same sites, with the same site pins, as Silinx's Map packs it, and
Silinx keeps writing their settings (the bitstream ISE's bitgen writes from them, byte for byte):
- the slices: the carry chains (a SLICEL a CARRY4, its LUTs those driving S, a DI from an O5 LUT or by the bypass input,
  the sum beside the carry out through the storage element as a gate, AND2L), the F8s with their F7s, the F7s two by
  two, the SLICEM's RAMs (RAM32X1S … RAM256X1S, RAM32M, RAM64M) and shift registers (SRL16E, SRLC32E) by their clock,
  write enable and address, then the flip-flops and latches beside the logic driving them when the control set allows,
  else beside a LUT, else with others of their control set; no LUTs packed together (ISE's map's `-lc off`);
- the IOBs, the BUFGMUXes, the block RAMs and the DSP48A1s, a site each; a cell it has no site for (a DCM, a PLL, a
  BUFIO2…) stops it, naming the cell;
- each site's timing arcs (`TMG`) from Silinx's model, `timing_model.h` (generated by Silinx's
  `research/nextpnr-s6/export-arcs.mjs` from its `timing-model.js`), as Silinx gives them for an unplaced site.

The netlist's cells go in their names' order (nextpnr reads them so): Silinx's Map, given the cells in that order,
packs the same sites. On Silinx's examples (`examples/`) for the XC6SLX16 and the XC6SLX45: the same sites, nets, power
pins and arcs as Silinx's Map, and as many slices as its Map in Yosys's order. Each site cell says what it holds in its
attribute `SILINX_PACK` (`netlist.cc`), for Silinx's settings: a slice's positions (`o6:A=<cell>`, `ff:B=and2l`,
`mux:C=xor`…), another site's cell (`cell=<cell>`). The I/O buffers keep their attributes (`LOC`, `IOSTANDARD`, `DRIVE`,
`SLEW`, `PULL`, and `PORT`: the port bit, which names the IOB). The constants' pins are the nets `$s6_vcc` and `$s6_gnd`,
with no source: Silinx gives each its TIEOFF once placed (its second run).

The pads and global buffers (`pads.cc`), as Silinx's placer placed them (`place.js` placeS6, `sites.js`):
- a `LOC` on its pad (a fixed BEL): an error when it is no bonded pad of the device, when two ports take it, or when its
  bank's other I/Os need another VCCO (their `IOSTANDARD`s; LVCMOS25 when none);
- a global buffer driven by a pad on a BUFGMUX that pad's dedicated clock path reaches, nearest first (a clock input
  with no `LOC` first on a free GCLK pad whose buffer is free); the others on the free BUFGMUXes in order; a clock on a
  pad no dedicated path leaves, a warning (its clock routed on the general interconnect);
- the IOBs with no `LOC` on bonded pads, placed by nextpnr, each bank's I/Os of one VCCO. The banks are the CSG324's sides
  (UG381: 0 top, 1 right, 2 bottom, 3 left).

Not yet: the I/O logic's registers (ILOGIC2 / OLOGIC2, `IOB = TRUE`), the DCMs and PLLs, which Silinx's Map does not
pack either; the constants' TIEOFFs.

## The chip database

`gen/s6_gen.py` builds it from Silinx's device graph, with one BEL per site. `--unknown-pips` leaves out the PIPs whose
bits Silinx's bit database does not know; `--timing` gives each routing node its delay as Silinx's timing analysis counts
it (the node's class and wire type, a load's node the model's base and its pin kind's), which nextpnr adds to the PIP
driving the node, so a path's delay is Silinx's (a timing file without node classes: each PIP the delay of the wire class
it drives). A PIP's flags
say what `spartan6.cc` checks:
- a global clock, or a pad into its global buffer, stays off the general interconnect;
- a route-through of the I/O logic or a BUFH is for one net, on a site with no cell;
- COUT -> DMUX is only for that slice's own carry out, when DMUX is free.

## Timing

Each cell brings its own arcs in its `TMG` parameter, from Silinx's model fitted to ISE's `trce`.

## Placer

HeAP, then an annealing refinement whose moves reach 40 tiles (a block RAM or DSP48A1 is a sparse column away from the
next one), at temperature 0.01, 60 passes, criticality exponent 4 (`-o refine-temp=…`, `refine-diameter`,
`refine-passes`, `refine-critexp`). With it nextpnr places the block RAMs and DSP48A1s itself (Silinx #3137). A slice
cell goes only on a slice its type fits (`isBelLocationValid`: HeAP's legaliser tries the bucket SLICE's BELs with it).

## Router

`router2` is the default: it asks `checkPipAvailForNet`, while `router1` would ignore the rules above.

## Tests

`ci/build-and-test.sh` places and routes the test netlists of `tests/expected.txt` (no error, every net routed, the
maximum frequency at or above its floor), then packs those of `tests/pack.txt` (`ci/test-pack.sh`: each one's packing
line, warnings and errors exactly those listed): Yosys netlists of Silinx's examples and of `tests/pack-src/*.v` (every
kind of cell the packer takes), and the pads' rules. It also routes, on both devices, the netlists of `tests/pads.txt`
(no warning): a port LOC'd on a pad whose path goes through a PIP Silinx keeps out of its own flow until this chip
database has it (its `bitdb/s6/s6-pips-held.json`, which `export-unknown-pips.mjs` counts as known: pmnmalo/Silinx#3349).
`ci/test-wasm.mjs` runs them all in the WebAssembly build.

## Build

```
node <silinx>/packages/silinx-fpga/research/nextpnr-s6/export-unknown-pips.mjs xc6slx16csg324-3 <dir>/unknown-pips-xc6slx16.json
node <silinx>/packages/silinx-fpga/research/nextpnr-s6/export-timing.mjs xc6slx16csg324-3 <dir>/timing-xc6slx16.json
cmake -S . -B build -DARCH=himbaechel -DHIMBAECHEL_UARCH=spartan6 -DBUILD_PYTHON=OFF -DBUILD_GUI=OFF \
  -DSILINX_DEVICES=<silinx>/packages/silinx-fpga/devices -DSILINX_UNKNOWN_PIPS=<dir> -DSILINX_TIMING=<dir> \
  -DHIMBAECHEL_SPARTAN6_DEVICES="xc6slx16:csg324"
cmake --build build -j
```

`ci/build-wasm.sh` builds the WebAssembly package (`npm/`: `@silinx/nextpnr-himbaechel-spartan6`), as the Spartan-3E's.
A release is prepared in a pull request: its version in `npm/package.json` and its section in
[`npm/CHANGELOG.md`](npm/CHANGELOG.md); the tag `spartan6-v<version>` must be that version (`ci/build-wasm.sh` refuses
another), and a build without a tag is `<version>-dev.<commits>`. The tag's run (`.github/workflows/spartan6.yml`)
publishes the package and the chip databases as a GitHub release, and stages the package on npm by npm's trusted
publishing (this repository and `spartan6.yml`, set on the package's settings at npmjs.com), with its provenance. It
becomes public when the maintainer approves it, with 2FA: `npm stage list`, then `npm stage approve <id>`
(pmnmalo/Silinx#3141).
